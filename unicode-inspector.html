Complete User Guide to Unicode Code Points, UTF-8 Bytes, UTF-16 Surrogate Pairs & HTML Entities

How Unicode Code Points Differ From UTF-8 Bytes and UTF-16 Units

In Unicode, every abstract character or symbol is assigned a unique number called a code point, written in standard notation as U+XXXX (for example, U+0041 for A, U+0928 for न, or U+1F680 for 🚀). However, computers store and transmit code points using byte-oriented encodings such as UTF-8 (which uses 1 to 4 bytes per code point) or UTF-16 (which uses one 16-bit code unit for Basic Multilingual Plane characters U+0000–U+FFFF and a surrogate pair of two 16-bit code units for supplementary code points above U+FFFF). That is why a string's .length in UTF-16 JavaScript code units can differ from the number of visible code points or UTF-8 bytes. UTF-8 Byte Length Tiers by Code Point Range

UTF-8 encodes Unicode scalar values across four byte-length ranges so ASCII remains backward-compatible:

U+0000–U+007F: 1 UTF-8 byte (0xxxxxxx)  |  U+0080–U+07FF: 2 UTF-8 bytes
U+0800–U+FFFF: 3 UTF-8 bytes  |  U+10000–U+10FFFF: 4 UTF-8 bytes (UTF-16 surrogate pair)

Helpful Tips When Debugging Text & Encodings

  • Spot Invisible or Combining Marks: Zero-width characters, spaces, and Devanagari vowel/halant marks show up as distinct rows in the table so you never miss hidden characters.
  • Check UTF-8 Byte Counts for Database & Payload Limits: Non-Latin scripts and emojis often occupy 2–4 bytes per character in UTF-8 rather than 1 byte.
  • Use HTML Entities for Safe Markup Embedding: Numeric character references like ࠤ or 🚀 represent code points in HTML/XML.

Worked Example: Inspecting नमस्ते breaks the word into its constituent Devanagari code points—including base consonants and combining signs—alongside their U+09xx code points and 3-byte UTF-8 hex sequences.
