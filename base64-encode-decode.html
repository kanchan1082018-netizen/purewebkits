How Base64 Encoding, UTF-8 Byte Mapping & URL-Safe Base64 Work

Why Developers Use Base64 for APIs, Data URIs & Email Attachments

Base64 is a standardized binary-to-text encoding scheme (defined in RFC 4648) that converts arbitrary raw bytes—such as UTF-8 text, images, cryptographic hashes, or binary files—into a safe 64-character ASCII subset (A–Z, a–z, 0–9, +, and /, with = used for padding). Because legacy transport protocols like SMTP email, JSON payloads, XML documents, and HTTP Basic Authentication headers can corrupt raw non-printable bytes, Base64 guarantees data arrives intact across any network. When embedding small icons or fonts directly inside HTML or CSS, developers also use Base64 Data URIs (data:image/png;base64,...) to eliminate extra HTTP requests.

Base64 Encoded Size Expansion Formula & Worked Example

Base64 groups every 3 input bytes (24 bits) into 4 output ASCII characters (6 bits each), increasing payload size by approximately 33.3%:

Encoded Base64 Length (Characters) = 4 × ⌈ Input Bytes / 3 ⌉

Worked Example: Suppose you encode the 3-character ASCII string "Man" (3 bytes: 0x4D 0x61 0x6E).

In binary: 01001101 01100001 01101110 → split into four 6-bit groups: 010011 (19 = T), 010110 (22 = W), 000101 (5 = F), 101110 (46 = u).

Encoded Base64 output = "TWFu" (exact length: 4 × ⌈3 / 3⌉ = 4 characters with zero padding).
