How Binary JPEG JFIF & PNG pHYs DPI Headers and Print Sizing Work

Why Online Portals & Commercial Printers Reject 72 DPI Images

DPI (Dots Per Inch)—technically referred to as PPI (Pixels Per Inch) in digital imaging—is a physical print-density instruction stored inside the binary header of a JPEG (JFIF APP0 segment) or PNG (pHYs physical pixel dimensions chunk). Standard web browsers and smartphones typically save screenshots and photos with a default 72 DPI or 96 DPI tag. However, commercial offset printers, book publishers, passport agencies, and Indian government exam portals (such as UPSC, SSC, and state PSC portals requiring 200 DPI or 300 DPI) inspect that binary header before accepting uploads. Changing DPI metadata does not alter your pixel count or degrade sharpness—instead, it updates the binary density bytes so Adobe Photoshop, Microsoft Word, and automated portal validators recognize the exact physical print dimensions.

Print Inches & PNG Pixels-Per-Meter Formulas + Worked Example

Physical print size equals pixel resolution divided by DPI, while PNG pHYs chunks store resolution in integer pixels per meter (1 inch = 0.0254 meters):

Print Width (Inches) = Pixel Width / DPI  |  PNG pHYs (Pixels/Meter) = round( DPI / 0.0254 )

Worked Example: Suppose you have a crisp digital photograph measuring 1800 × 1200 px tagged at 72 DPI (which prints at 25.0 × 16.67 inches).

Changing the binary header to 300 DPI yields a sharp (1800 / 300) × (1200 / 300) = 6.00 × 4.00 inch postcard print.

For PNG export at 300 DPI, our engine writes round(300 / 0.0254) = 11,811 pixels/meter with a valid IEEE CRC32 checksum.
